## Cause and UX issue

`PlayerViewModel.pausePlayback()` calls `stopPlayback()` for radio. It stops the experimental session while the old item is still owned, so `RadioPlaybackSession.stop()` calls `finishRecording(reason: "item_teardown")`, writing an ended event and sidecar. Then `stopPlayback()` clears `streamExperimentSession`, so `isStreamExperimentCapturing` becomes false and `StreamExperimentView` removes the **Stop export** and marker buttons. Export status remains in the view model but appears near the bottom of a scrollable debug panel; the user experienced this as a reset. There is no user-visible persistent completed-capture summary at the top. A pause cannot stay in the same recorder because that item's generation is deliberately invalidated. A later resume needs a fresh item and, if captured, a separate trace; do not splice two traces or claim buffer continuity.
