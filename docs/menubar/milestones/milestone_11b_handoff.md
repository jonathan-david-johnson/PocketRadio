## Same-player export

In a Debug build, select **Observe only** or explicitly **Apply candidate**, start KCRW, choose the output-route *category* (not a device identifier), then press **Start same-player capture (reconnect)**. This starts a new item and traces it from its first feed/sample. Human marker buttons cover heard song change, lyric landmark, wrong title/line, and speech/commercial. Stop export explicitly or tear down the item. The popover displays the local trace path and decision sidecar name.

The trace uses Stream Lab schema-v1 bounded, exclusive, owner-only JSONL, with feed, paired AVPlayer observations, markers and end event. A separate versioned JSON sidecar records observation sequence, legacy title, candidate, occurrence ID, selection reason, and frozen policy; Apply exports also label mode `apply_candidate` and record the separately published title. It does not yet record lyric-resource provenance/timestamps or a publication revision. Both files are written under the user's Application Support `PocketRadio/StreamExperiment` directory; no audio or lyric text is recorded. Inspect/redact them before sharing. A missing sidecar or write/limit error reports an **incomplete** export. `stream-lab replay TRACE.jsonl` inspects raw observations offline. The first smoke trace's two, second trace's four, and third trace's six app occurrence transitions match M11-A core replay. Full per-decision comparison, attended Apply playback, and the planned on-route lyric/multi-song evidence remain outstanding before any rollout.
