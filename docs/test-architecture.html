The counts, spike commands and planned work below describe 2026-10-04. The maintained CarPlay harness and output suite are now merged to iOS trunk. 1. Summary

PocketRadio is a set of players for internet radio and Pocket Casts: an iOS app (a fork of Automattic's Pocket Casts), a macOS menubar app, a terminal player, and a Roku channel. One Supabase backend serves them all. Each player is its own git repo.

The short version
  • Most tests are fast unit tests that run on a developer's Mac with no network, account, or audio. They replace the outside world with fakes passed in at the edges.
  • Proof of timing and metadata behavior comes from replaying recorded real-station sessions offline (macOS only), plus attended listening checks by a person.
  • One new layer, an in-process "CarPlay harness", exists on iOS as an uncommitted spike. It plays a fake radio station through the real app code and reads what CarPlay would display. It has already found two real bugs that the unit tests missed.
  • Nothing runs automatically. We have no continuous integration of our own. Someone has to run the suites.

2. How we test

Seven working rules explain most of the code you will see. They are habits of this team, not a written standard.

1. Hermetic by default

A normal test needs no network, no login, no credentials, and no sound card. Tests that break this rule are separate and labeled (the Go integration tag, the iOS harness, attended captures).

2. Inject the edges

Code takes its outside dependencies as parameters or protocols: a URL session, a feed fetcher, an "episode loader", a "publish now playing" closure. Tests pass fakes. We rarely mock internals.

3. Contracts are shared files

Wire formats between apps live as golden JSON in contracts/. Each platform's tests read the same files, so the apps cannot drift apart silently.

4. Pure core, thin platform shell

The stream timing model (StreamSession) has no audio or UI code, so it is tested as plain functions. Platform code feeds it samples.

5. Record once, replay offline

Real station sessions are captured to JSON trace files. Later, the same traces are replayed with no network, so timing logic can be tested against real-world evidence.

6. State the evidence boundary

Each tool says what it can and cannot prove. A test that opens its own connection to a station does not show what the app's player heard. The repo's AGENTS.md has a routing table for this.

7. Humans own "does it sound right"

No test can tell whether a title changes at the moment the song changes. People listen and mark it. Acceptance of the menubar alignment work (M11, M12) was qualitative for this reason.

3. The layers

From cheapest to most realistic. A lower layer answers "is this piece of logic right?". A higher layer answers "do the pieces work together?". The iOS history shows why both are needed (see iOS unit tests).

LayerQuestion it answersWhere it livesSpeed
A. UnitIs this function, parser, or reducer correct?All projectsMilliseconds per test
B. Contract fixtureDo all apps read and write the same wire format?contracts/remote/, loaded by iOS and menubar testsMilliseconds
C. Integration with fakesDo the real classes work together when only the outside world is faked?Menubar StreamSessionIntegrationTests; iOS RadioPlaybackStarterTests; Go UI model testsMilliseconds to a second
D. Offline replayDoes the timing model pick the right song on recorded real sessions?Stream Lab (replay, select, compare)Seconds
E. In-process end-to-endIf a station plays this song, what does the phone's Now Playing screen show?iOS CarPlay harness (spike)3–30 s per scenario, real playback

Layers A–D run unattended. Layer E runs unattended but needs a Mac that stays awake and a dedicated simulator. Layer F can't be automated.

4. iOS unit tests

The iOS app is a fork of Automattic's Pocket Casts. About two thirds of its tests are upstream's, and we leave them alone apart from merging. Our additions are the radio features, the CarPlay radio integration, the configurable tab bar, and the PocketRadio widget.

What is faked in our radio tests

  • The network. Tracklist and iTunes calls take an injected URLSession. Tests give it an ephemeral session with a stub URLProtocol. Parsers are also tested directly on JSON strings.
  • The app's own collaborators. RadioPlaybackStarter takes protocols (RadioStationRegistering, RadioEpisodeLoading). Tests supply FakeRegistry and FakeEpisodeLoader and check what was called.
  • Persistent state. Newer tests give the store an injected UserDefaults(suiteName:). The model is TabLayoutStoreTests.
  • Wire contracts. RemoteCommandFixtureTests decodes the shared contracts/remote/*.json files into the iOS types.

What is real

  • The app process itself. The test host is the app, so singletons such as PlaybackManager and the system Now Playing center are the genuine ones. For example, CarPlayConnectionStateTests writes and reads MPNowPlayingInfoCenter directly.
  • The parsers, resolvers, and decision functions under test. We fake what is around them, not them.
Hazard: the test host is the app

UserDefaults.standard inside a test is the app's real preferences on that simulator. Older tests that wrote real keys once deleted a developer's saved tab layout and sent a bug diagnosis down the wrong path (iOS bug 1, iOS bug 2). New tests must inject their own defaults suite. The iOS AGENTS.md states this rule.

What these tests cannot see

They check pieces. They don't check what the pieces do together over time. The artwork bugs found in M13 show the gap: no unit test failed for either bug, and one existing unit test even asserts the behavior behind bug 4 (it expects a fallback to the top tracklist entry when the stream's title isn't in the list). This gap is why the harness in the next section exists.

How they run

  • make test_staging ONLY_TESTING=<target-or-class> runs xcodebuild test against a simulator chosen by name. It does not pin one by UDID.
  • The test plan UnitTests.xctestplan skips IAPHelperTests.
  • New test files placed under PocketCastsTests/Tests/<Feature>/ are picked up automatically (the folder is a synchronized group, so there is no project-file edit).
  • Formatting and linting: make format and make lint (SwiftLint).

5. iOS CarPlay harness

Spike, uncommitted Milestone M13. The experiments are done. The kept version (M13.1 and M13.2) is planned but not started.

Why it exists

CarPlay's Now Playing screen is drawn by iOS from one shared record, MPNowPlayingInfoCenter.nowPlayingInfo. Several code paths write to that record: the stream's title events, a tracklist refresh, an artwork download, a full rebuild on play or pause, and lyric sync. Bugs appear when those writers interleave, and no unit test exercises the interleaving. The harness lets us script a radio station, play it through the real app code, and assert what the record holds.

What the real app code runs

Everything in the picture's middle box is production code, unmodified apart from the four reset seams. The harness enters through the same function the Streams tab uses (RadioPlaybackStarter.play) and the station is the curated KCRW Eclectic 24 entry, so the artwork-resolution path is switched on exactly as in the shipping app.

What is faked, and what is not

FakedRealNot covered at all

  • The tracklist and iTunes responses
  • The artwork CDN
  • The station record (made up, but with the real KCRW identifier)

  • Lyrics, ACR fingerprinting
  • Signed-in accounts and sync

Reset: process-wide state

The test host is one long-lived process. Scenarios share singletons, and leftovers from one change the next one's result. Experiment E4 found that without a reset, a second scenario that starts on the first one's last song loses its artwork. Four seams fix it, each a few lines under #if DEBUG:

  • PlaybackManager: the "last artwork key" used to skip repeat lookups.
  • NowPlayingHelper: which station's song a rebuild would keep.
  • TrackArtworkResolver and RadioTracklistService: caches and in-flight state.

Two of the four sit in files that come from Automattic, which raises the cost of merging upstream. The rest of the reset uses public calls (end playback, clear the registry, clear the image cache, clear Now Playing).

Operational hazard: the Mac must stay awake

Real playback uses the host Mac's audio device. When macOS entered maintenance sleep during a run, playback failed with a CoreMedia error and every title wait timed out. Two attempts failed this way before the cause was found. Running under caffeinate -dimsu fixed it. The planned Make target will wrap xcodebuild in caffeinate.

Where it is going

  • Planned M13.1 turns the spike into kept code on feature/carplay-harness: a proper fake world, network guard, probe, reset seams, and the Gherkin runner.
  • Planned M13.2 adds the scenario suite. The rules it asserts (S1–S7, approved 2026-10-04) include "a new song never shows the previous song's artwork" and "pause and resume keeps the artwork". Scenarios for known bugs run as strict expected failures: the run fails if one starts passing, so a fix can't land without removing its marker.
  • Planned Later, the iOS alignment work (M14) will need an HLS station in this harness. The current fake serves ICY only.
  • Decided design choices: every scenario uses a real stream, not injected metadata (50 of 50 stable); the fake world runs in-process; the .feature files live in the shared contracts/features/ folder so other platforms can adopt them later (a draft exists but is uncommitted).

The macOS menubar player is the project's reference implementation for the Pocket Casts API and for the stream-timing logic. Its test setup is more layered than iOS's, because the hard problem there was timing: showing the song that is audible, not the newest row in a station's feed.

Replay: real evidence without the network

Attended sessions with KCRW (AAC over HLS) and KEXP (AAC with ICY titles) were recorded into JSON-lines trace files (8 files in docs/menubar/experiments/traces/). A trace holds the player's clock, timed metadata, feed rows as received, and human "song started" markers on one timeline. replay and select read only that file, so anyone can re-run the analysis later without a network or a station.

What replay proves and what it doesn't

It proves the model makes the same choices on the recorded evidence, every time. It does not prove the audio matched. The same-item alignment was accepted by ear (M11-B, M12). The formal accuracy targets (for example ±5 s for titles) are still unverified, and the docs say so.

Related tools

  • tools/stream-probe.py (in the shell repo) opens its own connection to a station and shows raw ICY headers and metadata. Use it to check whether a station's feed is stale. It shows upstream behavior, not what the app's player received.
  • The menubar app has a Debug-only capture mode. It only starts when explicitly asked and never by default.

7. Console, Roku, Supabase, web, Android

Console player (Go)

  • About 76 tests across 19 files. go test ./... is meant to be hermetic.
  • Fakes: local httptest servers stand in for the radio and Pocket Casts APIs. The audio player has a Fake implementation. The lookup for the mpv binary is swapped to test the "mpv missing" error. The Bubble Tea screen is tested by sending key messages straight to the model.
  • Real, and separate: make test-integration (Go build tag integration) plays a short silent WAV file through a real mpv. It needs mpv installed.
  • Pocket Casts protobuf encoding and the client are covered by their own tests.

Roku channel (BrightScript)

None There are no automated tests. The workflow is: build and deploy to a Roku on the local network, watch the debug console over telnet, and take screenshots (make roku-deploy, roku-telnet, roku-screenshot). Findings from device spikes are in docs/roku/spikes.md.

Supabase backend

None I found no automated tests for the SQL migrations or the pc-relay edge function (Deno). Rows are scoped by an x-user-uuid header, so a mistake here is a data-access question, not just a bug.

Web and Android

Not scaffolded. Docs exist under docs/web and docs/android. No test setup yet.

Repository hooks

The only automated check at commit time is a pre-commit hook (.githooks/pre-commit). It enforces that every CLAUDE.md is a one-line pointer to AGENTS.md. It does not run tests or linters. Install it with make hooks.

8. Shared contracts

The contracts/ folder in the shell repo holds files that more than one platform must agree on.

contracts/remote/ In use

Six golden JSON files for the cross-device remote control protocol: play, pause, stop, load-station commands, and iOS and macOS presence records. They are the inner payloads that travel over Supabase Realtime. The envelope is each platform's own concern. iOS and menubar tests find the files by path relative to the test source (#filePath) and check that their types decode them.

Rule: a change that affects the wire format starts by editing these files. Every platform's fixture test then shows what has to change.

contracts/features/ Draft, uncommitted

Plain-language Gherkin scenarios, such as "the display shows the title Song B and does not show red artwork". They are worded without iOS terms so Android Auto, the menubar, or another platform could later write its own step definitions against the same files. Only iOS would implement them first. A platform's known bugs are tracked in that platform's own test code, not in the shared file, since a bug on iOS says nothing about Android.

11. Running everything

From the shell repo root unless noted. make help lists the full set of targets.

# Menubar
make menubar-test
swift test --package-path pocket-radio-menubar/Packages/StreamSession
swift test --package-path pocket-radio-menubar/Tools/StreamLab

# Console
make console-test
make -C pocket-radio-console test-integration      # needs mpv installed

# iOS (from pocket-radio-ios/)
make test_staging ONLY_TESTING=PocketCastsTests
make test_staging ONLY_TESTING=PocketCastsTests/RadioTracklistServiceTests
make test_staging ONLY_TESTING=PocketCastsDataModelTests

# iOS CarPlay harness (from pocket-radio-ios/; the target keeps the Mac awake)
make test_carplay
make test_carplay CARPLAY_TESTS=CarPlayArtworkTests

# Roku (device on the network)
make roku-deploy

Conventions to know before you add a test

  • iOS: put new tests under PocketCastsTests/Tests/<Feature>/. Inject UserDefaults(suiteName:). Never commit without approval after manual testing.
  • Shell repo: stage explicit file paths only, because several sessions share one checkout. Never git add -A.
  • Milestone docs define "behaviors to test", one numbered, red-to-green item each. These double as the work-splitting plan.
